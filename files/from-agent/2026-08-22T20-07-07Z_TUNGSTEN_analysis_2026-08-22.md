## WARRANT#157 — Insufficient evidence (indicator weighting)
`g_IndWeight[k]` synthesis let an indicator with ZERO measured directional evidence this run
still get a real directional vote in the unified score, purely because its amplitude
(magnitude-vs-move-size) correlation cleared the weight floor. Direction and magnitude are
orthogonal — this was noise voting as signal. Fixed: the amplitude term now only amplifies an
already-proven weight, never manufactures one on its own.

## WARRANT#158 — Misaligned logic (TP/SL fallback seam)
`CalculateSmartTPSL()`'s broker-min-stop-distance fallback (tight-spread/low-ATR conditions)
pulled its RR ratio from `UpdateIntelligentTPSL()` — a wholly separate, non-regime-aware
heuristic loop — instead of the regime/session/Hurst-calibrated ratio this exact function had
just computed for this exact trade. Fixed to reuse the trade's own calibrated ratio.

## WARRANT#159 — Dead/unreachable path (pattern learning)
The 100-slot pattern-sequence library had no eviction policy — a confirmed-poor predictor
(accuracy <60%) could squat a slot forever, blocking better sequences from ever being learned.
Fixed with quality-based eviction (only replaces slots both proven-poor AND past their trial
period). Note: a related suspected defect (confidence field blind to accuracy) was traced and
found to have ZERO live effect — correctly NOT shipped as a fix.

## WARRANT#160 — Mathematical error (Kelly ceiling)
`CalculateKellyCeiling()`'s live win-rate floor was 0.50 — for any realistic reward:risk b>=1.0,
that made fullKelly always come out positive, so the formula's own "no edge -> minimum risk
only" branch could never fire from a genuine losing patch. A real aggregate WR crash to 30-40%
was silently treated as 50%. Lowered floor to 0.10 — the branch now works as designed.

## WARRANT#161 — Misaligned logic (ProbDB extrapolation)
The sparse-bucket extrapolation fallback claimed to use the "most similar populated pattern"
but never filtered by score strength — could blend in an unrelated bucket's win rate. Added the
missing similarity filter (±1 scoreRange, matching this file's own existing tolerance elsewhere).

## WARRANT#162 — Dead/unreachable path (signal-quality gate) — STRONGEST FINDING
`signal.confidence`'s floor was 0.50, but `ENHANCED_SIGNAL_QUALITY_THRESHOLD = 0.45` — whose OWN
comment records real historical values as low as 0.26. The floor had silently made Gate 2 of
`ValidateFlexibleGates` mathematically unreachable — it could never fail, downgrading a real
4-gate entry filter to 3 gates for EVERY signal, system-wide, and separately capping live
position-sizing from ever reflecting a genuinely weak setup. Lowered floor to 0.05. This is the
best-evidenced fix of the session — corroborated by the codebase's own pre-existing comments.

## WARRANT#163/164/165 — Misaligned logic (GMT-correction convention, mechanical sweep)
