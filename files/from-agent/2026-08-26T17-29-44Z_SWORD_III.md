# SWORD III — THE CORRECTION CAMPAIGN

**Builds on:** SWORD_MASTER.md (Parts I–XII). All charter rules, gates, and register items
remain in force. **Distinct goal:** SWORD II found things that were broken. SWORD III finds
things that were built wrong on purpose — logics that work exactly as designed, where the
design was the error — and replaces them at the root without orphaning what depends on them.
**Issued:** 2026-08-26, immediately following the IC null result (n=42,772).

---

# PART A — WHY A SEPARATE CAMPAIGN

A broken logic announces itself: a hang, a zero, a dead call site. A wrong logic runs clean
forever and quietly destroys value. Every gate in SWORD II was built to catch the first kind.
None of them would have caught the blended score, because the blended score never failed — it
computed a correct average of the wrong thing, every bar, for months.

The distinguishing test: if the code did precisely what its author intended and the outcome is
still harmful, it is a SWORD III item. No amount of auditing correctness finds these, because
they are correct.

**Rule III-0.** A SWORD III finding is never "this is buggy." It is always: this is working,
and working is the problem.

---

# PART B — THE CONFIRMED-WRONG REGISTER

Each entry: what it does, why it's wrong, the evidence, and the root class.

**W-1 — Blending indicators into a single score.** Does: combines weighted indicator votes
into one unified number. Wrong because: if components point opposite ways in different
regimes, blending averages them toward zero — a machine for cancelling your own signals.
Evidence: IC(|score|,won) = −0.0024, AUC = 0.4986 at n=42,772. Meanwhile WARRANT#176 found
Strong Bear forward 36% vs reverse 47% at n≥6,263 — a component with real directional
content, invisible in the blend. Root class: **destructive aggregation.**

**W-2 — Pooled win rate against a fixed break-even.** Does: compares an aggregate win rate to
31.25%. Wrong because: TP/SL are regime-calibrated, so b varies per trade, so p* = 1/(1+b)
varies per trade. A single break-even was never valid. Evidence: internal contradiction — the
system's own TP/SL logic disproves it. Root class: **category error.**

**W-3 — One instrument, one timeframe.** Does: all research on USDJPY M5. Wrong because:
performance scales roughly as signal quality × √(independent bets) — the lowest-breadth
configuration possible. Evidence: our own arithmetic — 5y single pair ≈ 2,122 n_eff/cell
(below floor); 5y × 6 pairs ≈ 6,203–12,733 (comfortably above). Root class: **breadth
starvation.**

**W-4 — Binary win/loss as the learning label.** Does: collapses every trade to one bit at
close. Wrong because: discards the entire path — MFE, MAE, ordering, duration. A trade that
ran +1.8 ATR before reversing scores identically to one that never moved. Evidence: the only
statistically real result (+1.396 ATR, t=+2.99) is path-based. Root class: **information
destruction.**

**W-5 — Entry-time-only evaluation.** Does: decides once, then goes deaf until TP or SL.
Wrong because: every subsequent bar answers the question the entry asked, and none of it is
consumed. Evidence: entry IC null; exit mechanism significant. Root class: **stale decision.**

**W-6 — TP/SL as terminators.** Does: two fixed lines end the position regardless of what the
market is saying. Wrong because: ends positions on price arithmetic rather than on evidence.
Root class: **stale decision.**

**W-7 — Kelly fed by a flat rolling-60 window.** Does: estimates win rate from the last 60 raw
outcomes. Wrong because: no regime awareness — averages across sign flips. It is W-1's error
relocated into the risk layer. Evidence: simulation — risk throttled to 0.13% during a 40%
true-WR window; Kelly alone finished 63 points below flat risk with deeper drawdown (37.3% vs
29.9%). Root class: **destructive aggregation.**

**W-8 — Expecting a strong signal.** Does: treats components at IC ≈ 0.03 as failures. Wrong
because: IC 0.03 is a strong signal by professional standards. The bar was set at a level
nobody achieves, so real signals were discarded as noise. Root class: **miscalibrated success
criterion.**

**Rule III-1** — the four root classes are the search index. Every unexamined subsystem is
swept for: destructive aggregation, category error, information destruction, stale decision. A
fifth class is added only when one is confirmed.

# PART C — THE REPLACEMENT PROTOCOL

Removing a wrong logic is more dangerous than fixing a broken one, because things depend on it.

**Rule III-2 — Removal creates orphans (the D3 signature, inverted).** `g_Risk.minRisk` sat at
0.0 because nothing assigned it. Delete the blended score and every consumer of it reads a
default — the identical failure, caused by removal instead of omission.

Mandatory before any removal: enumerate every read site of the logic being replaced. Each one
gets an explicit decision — rewired, defaulted deliberately with the default recorded, or
removed. A read site left to find its own default is a SWORD II incident created by a SWORD
III fix.

**Rule III-3 — Parity invariant.** Every replacement runs alongside the original, both
computing, both logged, before the original is removed. Divergence is recorded per bar. The
old logic is deleted only after the new one has been observed live on the same inputs.

**Rule III-4 — Blast-radius trace.** Before shipping, produce the dependency graph of the
logic being replaced: what feeds it, what it feeds, what shares its state. Anything two hops
out gets a named disposition. Precedent: `g_CurrentThreshold`'s 50+ write sites — the reason
that item is still correctly untouched.

**Rule III-5 — Replacements are reducers where they touch size.** §I.11 holds without
exception. A replacement that touches exposure is a terminal reducer or a bounded discount.
Non-regressive by construction.

**Rule III-6 — One correction per pass.** Corrections are not batched. A batched correction
whose net effect is negative cannot be attributed. One W-item per pass, parity-observed, then
the next.

# PART D — THE RESEARCH ENGINE (the SWORD III upgrade)

SWORD II's Part X derived solutions. SWORD III generates and eliminates many candidates before
deriving one.

**D-1 — Minimum three alternatives, always.** **Rule III-7.** No replacement is proposed until
at least three structurally different alternatives exist, each with its own failure mode
named. One alternative is a preference; three is a decision.

**Worked example — W-1, replacing the blended score:**

| Alt | Approach | Fails if |
|---|---|---|
| A | Per-component IC weighting, weights per regime cell, components allowed to disagree | Components are individually null, not just cancelling |
| B | Two-stage: components pick side at high recall, a second model decides whether to act | The side-picker is worse than random, not merely weak |
| C | Rank-space combination — combine orderings rather than magnitudes, immune to scale | Components have no consistent ordering to combine |

Each is testable on the existing 42,772-row export. None requires new data.

**D-2 — Adversarial pass.** **Rule III-8.** Every proposed replacement is attacked before it
is built. Required attacks: how does this fail silently? · what does it cancel or discard? ·
what happens when its inputs disagree? · does it re-create the class it replaces at a
different level? That last one is mandatory — W-7 exists because W-1's error was
re-implemented in the risk layer without anyone noticing.

**D-3 — Cross-domain analogy.** **Rule III-9.** For each problem, name at least one
structurally similar problem outside trading and state what that field does. The requirement
is a structural match, not a superficial one, and the analogy must be adapted, never imported.

**D-4 — Falsification written first.** **Rule III-10.** Before any replacement runs, its
failure condition is written down. A replacement without a pre-written falsification cannot
produce a positive result — only an unfalsifiable one.

**D-5 — Research informs, never decides.** Part X's D1–D7 hold. Problem stated in TUNGSTEN's
terms → requirements derived → then research → fit tested against the derived requirements →
adapted at root → thresholds derived from our own data. If adaptation produces no
modifications, the agent pattern-matched instead of solving (Rule X-1).

# PART E — BLINDSPOT PREVENTION

A correction campaign is more likely to create blindspots than an audit, because it changes
behaviour rather than repairing it.

- **E-1** — Every removed logic's read sites are enumerated and dispositioned. (Rule III-2)
- **E-2** — Every replacement is telemetry-checked on arrival. New logic emits new logs; each
  is classified CONSUMED or ORPHANED at the moment it is written (§I.3). A correction that
  ships an orphaned log has reproduced the sentinel failure.
- **E-3** — Every replacement re-runs the reducer stacking product. (§I.11/G-STACK) New
  discounts compose with existing ones. The worst-case simultaneous-trigger product is
  recomputed each time.
- **E-4** — Every correction is re-audited for its own root class. After shipping, the
  replacement is checked against all four classes. Does it aggregate destructively? Does it
  discard information? Does it decide once and go deaf? Is its success criterion calibrated?
  W-7 is the proof this is necessary.
- **E-5** — Capability rows are never removed, only downgraded. If a correction invalidates a
  capability, the row is downgraded with the reason. A build that loses a register entry does
  not ship.

# PART G — WHAT THIS CAMPAIGN CANNOT DO

It cannot create edge. Every correction removes a value-destroying mechanism. If nothing is
being destroyed, correction yields nothing.

It cannot be run indefinitely. Rule VI-1 stands: reframings cap at four, and corrections are
bounded by the confirmed-wrong register. A ninth W-item requires evidence, not dissatisfaction
with the first eight.

It cannot outrun its own success criterion. Rule III-10: falsifications written first. A
campaign that keeps correcting until results look acceptable is fitting the analysis instead
of the model.

**Rule III-11 — the honest terminal state.** If W-1 through W-8 are all corrected and the
system still shows no edge across instruments, the correct conclusion is that these components
do not contain one, and the correct response is different components — not a ninth correction.

# PART I — AUDIT THE EVIDENCE THIS CAMPAIGN RESTS ON

**Rule III-12.** SWORD III's entire confirmed-wrong register descends from one export. That
export has not been audited. Before any correction ships, the export gets the G-SELF treatment
(§I.7): a known-answer test.

This is the campaign's own blind spot. The OOS 0.0% result was correctly flagged as needing a
scorer self-test. The IC null was not — and it is now load-bearing for eight findings. Same
class of error, one level up.

**I-1 — Export known-answer test (blocking).** Inject synthetic rows with a known IC — a
score constructed to correlate with outcome at exactly 0.10 — into the pipeline. If the
analyzer does not return ≈0.10, the analyzer is wrong and the null is void. Also inject a
known-zero set and confirm ≈0. **Run before item 1 of Part F.**

**I-2 — Look-ahead check.** Confirm the score at row t uses no data from after t. A look-ahead
bug usually inflates IC, so it is an unlikely cause of a null — but if the export mis-joins
score to outcome (off-by-one, wrong key), IC collapses to zero regardless of true signal. Test:
deliberately shift the join by one row and confirm IC changes. If it doesn't, the join is
broken.

> **RESOLVED, pass_183.** A shift+1 test did show a real anomaly (IC jumped to +0.075-0.086 from
> -0.006 unshifted) that survived a filtering-confound fix — but a direct follow-up measurement
> found `IC(won[t],won[t+1])=0.68` and `IC(score[t],score[t+1])=0.79`: both series are massively
> autocorrelated by construction (20-bar overlapping lookahead windows share ~19/20 bars between
> adjacent rows). This fully explains the shift anomaly with no join defect required, and matches
> the code-level join-logic audit's conclusion (no off-by-one found). I-2 closed with a real
> mechanism, not a caveat. See `research_layer/audit_export_evidence_round2.py`.

**I-3 — Censoring bias (14.5% of the sample).** 50,000 rows exported, 42,772 resolved — 7,228
unresolved (14.5%). Unresolved trades are not missing at random: a position still open is
disproportionately one that has not yet hit a barrier, which correlates with slow or ranging
conditions. Dropping them silently conditions the entire sample.

Required: report resolved-rate by regime and by score decile. If the unresolved fraction
varies materially across score deciles, the null is measured on a biased subsample and must be
recomputed with censoring handled.

**I-4 — What the null actually rules out.** Our arithmetic, at n=42,772:

| Quantity | Value |
|---|---|
| Standard error of IC | 0.00484 |
| 95% CI on the observed −0.0024 | [−0.0119, +0.0071] |
| Smallest IC detectable at 80% power | 0.0135 |

Correct reading: IC ≥ 0.0135 is ruled out. IC = 0.03 — the professional "strong signal" level
— is comfortably excluded by the CI. That is a real, decisive finding and W-1 stands.

But IC ≈ 0.005 is **NOT** ruled out. It sits inside the interval. At sufficient breadth a
signal that small is not automatically worthless.

**Rule III-13.** State results as intervals, never as "null." "IC = 0, no edge" is the same
class of overstatement as "ghostWR 100%." The honest sentence is: the blended score's IC is
below 0.0135 with 80% power, and a strong signal is excluded.

# PART J — THE CAMPAIGN'S OWN SELECTION BIAS

**Rule III-14.** SWORD III tests many alternatives. That is multiplicity, and it applies to
corrections exactly as it applies to strategies.

| Tests run | P(≥1 false positive at α=0.05) |
|---|---|
| 8 (one per W-item) | 33.7% |
| 24 (three alternatives each) | 70.8% |
| 50 | 92.3% |

Part D mandates three alternatives per item. That is 24 tests, and a 71% chance of at least
one looking good by luck alone.

Requirements:
- Every correction result is deflated by the total number of correction tests run across the
  whole campaign, counted from the ledger — not per item, not per pass.
- The count includes abandoned alternatives. An alternative examined and dropped was still a
  test.
- Any correction that survives only without deflation is recorded as a LEAD, never shipped.

**Rule III-15 — pre-register.** Before running item 1, write down all three W-1 alternatives,
their predicted outcomes, and their falsification conditions. Post-hoc alternatives are
permitted but counted separately and held to a stricter threshold.

# PART K — PARITY HAS A PATH-DEPENDENCE FLAW

Rule III-3 requires old and new logic to run side by side. This is invalid the moment the new
logic can influence what happens.

If a replacement changes exposure, it changes which trades exist, which changes the inputs the
old logic sees. The two are no longer being compared on the same data — they are being compared
on two different histories.

**Rule III-16.** Parity comparison is valid only in replay or shadow, where neither logic
affects execution. Live parity is a correctness check on the engine (do both compute what
replay said they'd compute), never an evidence source. This is Rule XII-0 applied to
corrections.

**Rule III-17 — frozen baseline.** A reference build is frozen at campaign start and never
modified. Every correction is measured against the frozen baseline on identical replay data —
never against the previous correction. Otherwise improvements chain and a regression three
corrections back becomes invisible.

# PART L — REGRESSION AND ROLLBACK

**Rule III-18 — zero-regression law.** Every prior capability that passed before a correction
must pass after it. The full capability register (R-1…R-10) is re-run on every correction. A
correction that improves its target while silently degrading another capability is a net loss,
and without this check it looks like progress.

**Rule III-19 — rollback path.** Every correction ships with a stated revert: the exact
commit, the ledger pass, and the read sites that must be restored (Rule III-2 in reverse). A
correction that cannot be cleanly reverted is not shipped.

**Rule III-20 — correction expiry.** A correction whose measured benefit is not confirmed
within 30 days of shipping reverts to UNPROVEN and is re-examined. This is G-STALE applied to
changes rather than to blockers, and it exists because a correction believed-good-but-unmeasured
is exactly how WARRANT#160's dead Kelly fix survived.

# PART M — INTERFERENCE AND DOUBLE-COUNTING

**Rule III-21 — corrections interact.** Fixing W-1 changes the data W-7's estimator sees.
Fixing W-2 changes the metric W-8 is calibrated against. The queue order in Part F is a
dependency order, not a priority list, and reordering requires re-deriving the dependencies.

**Rule III-22 — collapse correlated items.** W-4 (binary label), W-5 (entry-only evaluation)
and W-6 (TP/SL as terminators) are one underlying error — the position is not re-read while
open — counted three times. Treating them as three separate wins inflates apparent progress
threefold.

They are hereby merged into **W-4 — "the position is decided once and never re-read."** One
item, one correction, one measurement. The register is eight entries long only if the entries
are independent; it is genuinely six.

**Rule III-23 — component independence.** Per-component IC (Part F item 1) overcounts if
components are correlated. Report the component correlation matrix alongside individual ICs.
Five components at IC 0.02 that are 0.9 correlated with each other are one signal at IC 0.02,
not five.

# PART N — TERMINATION

**Rule III-24 — the campaign has a defined end.** SWORD III completes when all six W-items
reach a terminal verdict under Part IV.2 (FIXED/REFUTED/BLOCKED), with deflation applied per
Part J and regression clean per Rule III-18.

**Rule III-25 — the exhaustion criterion.** If all six are corrected, deflation-surviving,
regression-clean, and the system still shows no edge across six instruments: the components do
not contain an edge. The response is different components, different instruments, or a
different timeframe — never a seventh W-item.

**Rule III-26 — the false-progress test.** At campaign end, compare the frozen baseline
against the final build on identical replay data. If total R has not improved, the campaign
removed nothing that was destroying value, regardless of how many items were marked FIXED.
That comparison is the only measure of the campaign that counts.

# PART H — THE THESIS

SWORD II asked whether the machinery was honest. It is. SWORD III asks whether the machinery
was pointed at the right thing.

The evidence says no in eight specific, named ways — and every one of them was a design
decision made deliberately, working exactly as intended, destroying value silently while every
correctness check passed.

The most expensive logic in a system is never the broken one. It is the one that works.

And the campaign that corrects it is subject to every discipline it enforces: its evidence
audited before it is believed, its own multiplicity deflated, its parity protected from path
dependence, its progress measured against a frozen baseline rather than against its own last
step.

**A correction campaign that exempts itself from its own rules is the most expensive logic of
all.**
